## 开篇词｜为什么你的文献库，读完就是坟场

**目标**：不讲方案，只讲问题，让读者认同"知识管理≠存档"这个判断标准，为后续六讲建立评价框架。

1. 场景引入
   - 下载 PDF → 读完关掉 → 三个月后想不起来的经典场景
   - 提炼问题本质：只解决了"存"，没解决"连"
2. 三种主流方案逐个拆解失效原因
   - Notion：自由度高 → 无约束 → 标签体系随方向漂移，新旧笔记不兼容
   - Zotero：标注强 → 但标注与知识体系是两张皮，理解活在另一个系统里
   - 纯 Markdown：轻量灵活 → 无连接机制，笔记互为孤岛，数量增长≠效率增长
3. 给出可操作的评价标准
   - 标准句："你读的第 50 篇论文，有没有让前 49 篇变得更好理解？"
   - 展开标准背后的分野：知识合成发生在"查询时"还是"摄入时"
   - 类比：现算 vs 复利
4. 专栏地图
   - 一句话介绍 ReadR 的定位反转：AI 不是作者，人是作者
   - 六讲清单 + 每讲一句话钩子（不展开内容，只做预告）
5. 收尾
   - 思考题：找出最近读的三篇论文，能否一分钟说清楚彼此关系；卡在"存储"还是"连接"

## 01｜四层架构：给论文管理设计一套"读写权限"

**目标**：讲清楚为什么要分层、每层的权限边界、以及从三层到四层的演进逻辑是什么问题倒逼的。

1. 导读：你将获得
   - 一套可以直接套用的四层目录结构
   - 判断"某类内容该放哪一层"的三条权限规则
   - 一个反例，看不分层会具体死在哪一步
2. 从一个反例说起
   - 场景：在 sources/ 里直接对 PDF 做标注和修改
   - 后果：半年后不确定哪个版本是"原始状态"，引用页码对不上，版本混乱不可追溯
   - 归因：没有把"不可变"和"可编辑"分开，是大多数系统混乱的起点
3. 四层结构逐层拆解
   - `sources/`：只读原始材料，papers/ web/ books/ talks/ misc/ 分类逻辑
     - 权限规则：AI 不能改，人也不能改
     - 为什么：保证任何时候回头看都有一个可信的"地面真相"
   - `library/`：人工策展的论文目录 + 知识节点
     - entries/ 一文一档，YAML frontmatter 承载结构化元数据
     - concepts/ authors/ datasets/ benchmarks/ comparisons/ syntheses/ projects/ 各自的定位
     - 权限规则：AI 辅助生成，人最终确认
   - `annotations/`：精读笔记，只对 status: close-read 的论文开放
     - 与 library entry 通过 annotation 字段建立单向引用
     - 权限规则：AI 可起草，人必须完成"个人评价与思考"部分
   - `reviews/`：综述产出层，多格式（md/pdf/tex/bib）
     - 权限规则：人写作，AI 不碰
4. 三层到四层：Karpathy LLM Wiki → ReadR 的演进逻辑
   - Karpathy 原始三层：raw/ → wiki/ → schema/，AI 是知识的主要作者
   - ReadR 增加的两层解决了什么具体缺口：
     - 精读层缺失 → 机器摘要不能替代逐行读公式、读消融实验
     - 输出层缺失 → wiki 本身是终点 vs 综述才是终点
   - 一张对比表：架构层级 / 知识作者 / 元数据支持 / 阅读模型 / 输出目标（可复用已有论文草稿里的表 1）
5. 小结
   - 一句话总结：分层的本质不是目录整洁，是给"人"和"AI"划出清晰的责任边界
6. 思考题/练习
   - 把你现在的文献文件夹按四层重新归类一遍，看看有多少内容其实混在一起放的

## 02｜元数据设计：YAML frontmatter 与 wiki-link 拓扑

**目标**：讲清楚字段设计的取舍逻辑，让读者能现场为自己的研究方向设计一套 schema，而不是照抄模板。

1. 导读：你将获得
   - 一份可复用的 YAML 字段清单及每个字段的设计动机
   - 三段式阅读状态模型（to-read/browsed/close-read）替代布尔值的理由
   - 现场演示：为 KG+LLM+Agent 方向设计一套 tag 体系
2. entry 元数据逐字段拆解
   - title / authors / venue / doi：基础学术元数据，为什么比"文件名"更可靠
   - tags 的 category/key 设计：direction/ method/ task/ status/ venue/ 分类逻辑
     - 对比反例：无结构的自由标签，为什么半年后会漂移失效
   - status 三段式：to-read → browsed → close-read
     - 为什么不是布尔值"读过/没读过"：browsed 和 close-read 对应完全不同的 AI 介入深度
   - annotation / concepts / authors_related / datasets / benchmarks：链接字段
     - 这些字段是 wiki-link 拓扑的锚点，不是装饰性元数据
   - rating：主观评分存在的意义——量化你自己的判断，而不是论文的客观质量
3. wiki-link 拓扑如何把孤立笔记连成网络
   - 拓扑图：论文 → 概念/作者/数据集/基准/对比 → 综述 → 综合概述
   - 与 RAG 的嵌入相似度对比：显式链接 vs 隐式关联
     - 显式链接的可解释性：你清楚知道两篇论文为什么被关联，而不是"向量距离近"
   - 反例：两篇论文讨论同一概念但用词不同，嵌入检索容易漏掉，显式 tag 不会
4. 现场演示：设计一套 KG+LLM+Agent 方向的字段 schema
   - direction/kg-llm、direction/agent-kg 这类顶层方向标签怎么定
   - method/ 标签的颗粒度怎么把握（太粗没有区分度，太细维护成本高）
   - 一个具体 entry 示例（用 MASTER 或 DoubleAdapt 这类真实论文举例）
5. 小结
   - 元数据设计的核心原则：字段服务于"未来能不能被检索和关联"，不是为了填表而填表
6. 思考题/练习
   - 给你正在读的研究方向写一版 tags 体系草案，标出哪些字段是必须的，哪些是可选的

## 03｜人机分工：AI 能替你做什么，不能替你做什么

**目标**：给出一份可执行的"AI 介入清单"，划清 BROWSE 和 CLOSE-READ 阶段的自动化边界，并给出这条边界背后的论证。

1. 导读：你将获得
   - 两种协作范式的对比框架（AI 主导 vs 人类主导）
   - 一份分阶段的 AI 介入清单，可以直接对照执行
   - 判断"这件事能不能交给 AI"的一条通用测试
2. 两种范式对照
   - Karpathy 模式：AI 代理主导知识编译，人类做策源、探索、审核
     - 优势：维护成本趋近于零
     - 风险：错误一旦固化到 wiki 页面比单次查询错误更隐蔽、更持久
   - ReadR 模式：人类策展，AI 辅助
     - 用阅读状态模型划分 AI 介入粒度：browsed 阶段大规模用 AI，close-read 阶段人必须深度参与
3. 一条通用测试：这件事能不能交给 AI？
   - 测试问题："如果 AI 生成的内容有错，错误会不会被人在后续步骤里自然发现？"
   - BROWSE 阶段：错误容易被后续精读发现 → 可以放心交给 AI
   - CLOSE-READ 阶段：个人评价与思考如果被 AI 代写，错误（或者说"假理解"）不会被任何后续步骤检查出来 → 必须人做
4. AI 介入清单（可直接执行）
   - BROWSE 阶段
     - 提取核心概念 → concepts/
     - 提取研究者信息 → authors/
     - 提取数据集/基准 → datasets/、benchmarks/
     - 生成方法对比表 → comparisons/
     - 起草 syntheses/ 概述（3 篇以上后）
   - CLOSE-READ 阶段
     - 按模板生成笔记初稿，图表公式按对应小节穿插解释（不是文末汇总）
     - 唯一强制人工项：个人评价与思考（六段式笔记的第六部分）
   - REVIEW 阶段
     - AI 提供模板和结构建议
     - 论点、分析、结论完全人工
5. 为什么"个人评价与思考"不能被压缩
   - 论证：精读的终点不是"读懂了"，是"你有话想说"——这是机器摘要天然缺失的部分
   - 反例：AI 代写的"评价"通常是复述摘要，缺少可质疑的具体观点
6. 小结
   - 分工原则一句话：AI 负责"提取"和"起草"，人负责"判断"和"下笔"
7. 思考题/练习
   - 回顾你最近用 AI 辅助读论文的一次经历，对照清单，看看哪一步其实应该由你自己做但被你外包给了 AI

## 04｜知识沉淀的最小动作：从浏览到精读

**目标**：把"浏览时沉淀"从口号变成可执行的动作序列，并拆解精读笔记六段式结构的写作方法。

1. 导读：你将获得
   - 一套"读一篇论文"时的最小动作单元清单，可以边读边做
   - 精读笔记六段式结构的分段写作方法
   - 为什么"读完再统一整理"几乎必然失败的具体原因
2. 反模式先行：读完再整理为什么会失败
   - 时间衰减：细节在读完的当下最清晰，拖延整理会让"理解"退化成"印象"
   - 批量整理的心理成本：面对一堆待整理的论文，人会本能地选择泛泛而过
3. 浏览阶段的最小动作序列
   - 读摘要 + 引言 → 写一段自己的总结（不是翻译摘要，是自己的话）
   - 打标签（对照 02 讲设计的 schema）
   - 顺手动作：
     - 遇到新概念 → 立刻建 concepts/ 条目（哪怕只有一行）
     - 遇到可比方法 → 立刻在 comparisons/ 开一行对比表
     - 同方向满 3 篇 → 触发写 syntheses/ 的动作
   - 状态更新：status 从 to-read 改为 browsed
4. 精读笔记六段式结构逐段拆解
   - 一、基本信息：标题/作者/年份/关键词，纯记录，不展开
   - 二、摘要与核心问题：用自己的话概括，重点是"研究背景与动机"——为什么做这个研究
   - 三、核心方法：架构图逐模块解释 + 公式逐符号解释，图表公式必须穿插在对应小节，不能文末汇总
   - 四、实验与结果：数据集/基线/指标 → 主要结果 → 消融研究，关键图表必须解读而非罗列
   - 五、讨论与分析：主要贡献、优势、局限性（含"你认为还存在哪些局限"）、未来工作
   - 六、个人评价与思考（最重要且最容易偷懒）
     - 四个子问题：个人理解 / 启发 / 疑问 / 可改进之处
     - 写作方法：不是总结论文，是要提出一个可以被反驳的具体观点
5. 一个简短的真实案例演示
   - 用 MASTER 或 DoubleAdapt 其中一篇，展示从"打开 PDF"到"写完第六部分"的完整动作轨迹
6. 小结
   - 核心原则：知识沉淀不是精读之后的额外步骤，是浏览时顺手完成的动作
7. 思考题/练习
   - 挑一篇你正在读的论文，现在就完成"浏览阶段最小动作序列"，计时看花了多久

## 05｜工具化：把工作流封装成可复用的 Agent/Skill

**目标**：从手工四步流程过渡到自动化，明确哪些环节可以封装、哪些判断动作必须保留人工介入。

1. 导读：你将获得
   - INGEST 阶段自动化的具体实现思路（元信息提取、条目初稿生成）
   - 一份"自动化边界清单"：哪些动作可以封装成 Skill/Agent，哪些不行
   - 承接 ReadR 仓库 README 里"还没做的事"，给出可以自己动手扩展的方向
2. 为什么从 INGEST 阶段开始自动化
   - INGEST 是最机械、最少判断的环节：下载 PDF → 提取元信息 → 生成条目框架
   - 用 Claude Code / MCP 实现的思路：读 PDF → 抽取 title/authors/venue/doi → 生成带 YAML frontmatter 的 entry 初稿
3. 自动化边界清单
   - 可以完全自动化：元信息提取、条目框架生成、BROWSE 阶段的概念/作者/数据集提取、对比表生成
   - 需要人工确认后再落盘：syntheses/ 概述起草、精读笔记初稿
   - 绝不能自动化：个人评价与思考、综述的论点与结论
   - 判断标准复用 03 讲的测试："错误会不会在后续步骤被自然发现"
4. 承接仓库里"还没做的事"，逐条给出具体思路
   - Agent 工作流编排：用 Skill/MCP 把四步管线封装成可复用任务
   - 独立应用：带 UI 的 Web/桌面端，降低使用门槛
   - PDF 入库自动生成条目初稿的具体脚本思路
   - 精读模板的多语种/多风格变体
   - 与 Zotero 等工具的桥接可能性
5. 一个可以现场跟做的最小自动化示例
   - 伪代码/流程图：PDF → 元信息提取 → entry 初稿 → 人工确认 → 落盘
6. 小结
   - 自动化的目标不是替代判断，是把机械劳动交出去，把时间留给"判断"和"下笔"
7. 思考题/练习
   - 挑一个你手工重复做过最多次的动作，判断它落在自动化边界清单的哪一档

## 06｜实战复盘：KG+LLM+Agent 方向，从 0 篇到能写 survey

**目标**：用真实科研经历完整走一遍四层工作流，展示方法论如何真正落地成一份可发表综述的大纲，并收束整个专栏。

1. 导读：你将获得
   - 一个真实科研方向从零散阅读到 survey 大纲的完整轨迹
   - 具体展示 close-read 论文清单（如 MASTER、DoubleAdapt）如何沉淀进 syntheses/
   - 专栏方法论的最终检验：能不能真的写出一份 CCF-A 级别的综述框架
2. 起点：探索阶段的三个子方向
   - LLM-KG 融合、Agent-KG 系统、量化交易应用，如何用四层结构筛选出研究空白点
   - library/entries/ 里最初几篇论文的粗筛过程
3. 中段：BROWSE 到 CLOSE-READ 的具体轨迹
   - 哪些论文进入了 close-read（MASTER AAAI'24、DoubleAdapt KDD'23 等）
   - concepts/ 和 comparisons/ 里沉淀了哪些关键节点
   - syntheses/ 如何把这些节点归纳成"量化交易自动策略生成"这个子方向的定位
4. 终点：从 syntheses 到 survey 大纲
   - 具体展示 review 框架的骨架：方法设计 / baseline 选择 / 消融实验结构 / 三个月执行时间线
   - 强调：这份大纲不是凭空写出来的，是四层结构里沉淀的节点直接拼出来的
5. 复盘：这套方法论真正沉淀下来的是什么
   - 不只是一篇 survey 大纲，是可复用给下一个研究方向的完整流程
   - 呼应开篇词的评价标准："第 50 篇论文有没有让前 49 篇更好理解"——用这个案例验证标准成立
6. 专栏收尾
   - 六讲内容一句话回顾
   - 给读者的最后一个行动建议：不要照抄 ReadR 的目录结构，先用自己的研究方向跑一遍最小闭环
7. 思考题/练习（专栏最终作业）
   - 用你自己的研究方向，跑一遍 INGEST → BROWSE → CLOSE-READ 的最小闭环（至少 3 篇论文），写出你的第一份 syntheses/ 草稿
